Read `docs/explorations/README.md` first, then `docs/labs.md` if it exists.

This box already has two 3D-adjacent services: **SAM 3D Body** (human mesh and
pose from one image, tab "3D Body") and **SAM 3** (segmentation). Neither
generates a general object. Read how they are wired before adding anything.

**Research first.** Candidates in late September 2026: **TRELLIS 2** (Microsoft,
MIT, ~4B, sparse-voxel, PBR materials, GLB export up to 4096² textures, image
input only, ~24 GB), **Hunyuan3D 2.x** (Tencent), **TripoSR / TripoSG** (fast
feed-forward). Verify what is current. **Check Hunyuan3D's licence carefully —
Tencent's community licences have excluded some regions and capped commercial
use**; say exactly what it permits.

**The pipeline I want to see work end to end on this box:**

1. Generate an object image locally (the image models are already here).
2. Segment or remove its background (SAM 3 is here).
3. Turn it into a textured mesh.
4. **Look at it in the console** — an interactive viewer (orbit, lighting,
   wireframe toggle), and a download as GLB.

Step 4 is the Lab. A 3D Lab without a viewer is a file-download page.

**Measure:** time and peak VRAM per model; mesh quality on a small fixed set —
a hard-surface object, an organic one, something with thin parts, a character;
topology (polygon count, holes, whether it is printable); texture resolution.
Compare the fast feed-forward model against the slower high-quality one, because
"under a second" and "the best mesh" are different products.

**Cloud comparison:** if a cloud image-to-3D API is reachable through the router
or with an existing key, run the same set; otherwise say that none was compared.

**Questions I care about:** is the quality good enough for a game asset, a 3D
print, or a product mockup? Which of those is it closest to?

**Deliverables:** the service, a 3D Lab with a viewer, an MCP tool if agents
would use it, and `docs/3d-model-experiment-2026-09-XX.md`, recommendation
first. Commit to `master`.
