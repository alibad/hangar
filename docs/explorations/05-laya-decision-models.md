**Laya** is an open decision model from Convai Innovations, released
18 September 2026 under Apache 2.0, positioned as the open-source alternative to
**Jev** (TypeSafe). It is not a text generator: ~421M parameters on a
ModernBERT-large backbone, it answers *typed* questions — pick one of these
choices, score this, yes or no — with calibrated probabilities in one forward
pass. Claimed 32.8 ms on a T4, 100+ languages, 7.8× faster than Jev.

Everything in that paragraph is the vendor's claim and it is days old. **Verify
it**: the weights, the licence, the checkpoints, the multilingual routing, the
latency on this card, and whether the calibration holds. Find out what Jev
actually is and whether it can be compared directly — if it is a paid API I do
not have a key for, say so and compare against what I do have.

**Why this matters on this box.** A 30B model is the wrong tool for a yes/no
question: it takes seconds, and its "confidence" is not a probability. At 421M,
Laya can stay resident permanently beside everything else. The question is
whether it is *right* often enough to replace an LLM call.

**Test it on decisions I actually make.** Build a small labelled set — tens of
examples each, honestly labelled, not generated by the model under test — for
several of these:

1. **Router escalation** — should this request go to a local model or a cloud
   one? The AI Router (`config/ai-router.yaml`) chooses by capability today and
   never by difficulty.
2. **Feedback triage** — Globe Quest's feedback widget files GitHub issues on
   `alibad/globe_quest`: bug, feature request, content correction, or noise?
3. **Relevance scoring** — the `reddit-scout` skill scores Reddit posts for
   relevance to my products. Could Laya do that part?
4. **Moderation** — Globe Quest's community feed and Ask Locals.
5. **Intent** — what is a chat message in the console asking for?
6. **Language and dialect** — Arabic is in scope; see
   `docs/arabic-model-experiment-2026-09-14.md`.

Use existing data as read-only fixtures. Do not wire globe_quest to anything
local.

**Compare, on each set:** Laya against a local LLM (`local-gemma4`) and a cheap
cloud model (Claude Haiku through the router) — accuracy, **calibration**
(expected calibration error, a reliability plot), latency, and cost per thousand
decisions. Say where Laya loses; the interesting answer is the boundary.

**Build:** Laya as a service; a `POST /api/decide` taking a question, typed
choices and a context, returning choice, probabilities and latency; a Decision
Lab in the console where I can type a question and choices and see the
distribution; and an MCP tool. The BPMN brief (06) will call `/api/decide` from
its decision gateways, so keep the contract simple and document it.

**Deliverables:** the service, `/api/decide`, the Lab, the labelled sets,
`docs/decision-model-experiment-2026-09-XX.md` with a recommendation **per use
case**. Commit to `master`.
