# How the 2026-09-19 capture set was produced

The images under `docs/images/console/` came from **three runs of
`scripts/walk-console.mjs` on 2026-09-19**, not one. Recording that here because
a run record describes one run, and this set spans several.

| Run | Target | What it produced |
|---|---|---|
| 1 | `--host b5` | All ten B5 captures |
| 2 | `--host betenshi` | Home, Services, Models, Chat, Usage, Requests |
| 3 | `--host betenshi --features image,speech` | Image Studio and the Speech Lab, after two walk bugs and a capacity problem were sorted out |

## Why run 3 was needed

**The walk was wrong twice before the app was.** Both failures looked exactly
like broken features, and neither was:

- `clickText("Generate")` matched **two** controls — the mode tab and the
  composer button — so the click never landed and the walk waited seven minutes
  for an image nobody had asked for. Same shape in the Speech Lab, where two
  buttons say *Speak*: the walk clicked the voice-cloning one, got a microphone
  permission prompt a headless browser can never satisfy, and reported that the
  host had no TTS service. It had one.
- The first speech attempt looked for the TTS box on arrival. The Speech Lab has
  two panes and mounts one at a time, so the box does not exist until
  *Text → speech* is selected.

The lesson worth keeping: **when a walk reports a feature missing, suspect the
walk first.** An ambiguous selector and an absent feature produce identical
output.

## Environment changes made for the walk, and undone after

Image Studio genuinely could not run at first, and the reason was correct
behaviour: starting Whisper, Kokoro, Chatterbox and Qwen-Image alongside the
already-running vLLM over-subscribed a 31.8 GB card, and the console's capacity
guard refused the job with a 409:

```
VRAM needs 20.2 GB more plus 0 GB reserved and 0.02 GB safety,
but only 2.76 GB is currently free
```

`vllm-small` was stopped to free 17.5 GB, the image generated, and **every
service was returned to the state it was found in** — verified by comparing the
up-set before and after.

## One capture was taken through a localhost proxy

`crypto.randomUUID()` exists only in a secure context, so Image Studio crashed
when the console was opened over the LAN by IP. That bug is now fixed in this
repository, but the BeTenshi box still runs its own older build, so the image
capture was taken through a `localhost` proxy — which is the same secure context
a user sitting at that machine already has.

## The BeTenshi box runs code that is not in this repository

Its Speech tab is a two-pane "Speech Lab" with voice cloning; this repository's
is a single simpler pane. So the BeTenshi captures document **that machine's
build**, which is ahead of `main`. Worth resolving before anyone treats these
images as documentation of the committed code.
