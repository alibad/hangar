# 2026-09-19 — Ready to share

Preparing the repository for other people to read. The code was already in good
shape; the gap was that nothing told a stranger what this is or how to run it on
their own machine.

## What We Built

**A README.** There wasn't one. Anyone landing on the repository saw 136 source
files and no statement of purpose. It now opens with what the console is, the
problem it solves, the one idea worth understanding (host profiles), a quick
start, a tour of each surface, and an honest status section.

**Screenshots that are evidence rather than decoration.** Every image in the
README was produced by driving the live console in a real browser via a new
`scripts/walk-console.mjs`, including a real prompt answered by the local
27B model. The capture layer verifies Retina density, viewport fidelity, frozen
animation and frame-distinctness by measuring the output rather than trusting
the flags it passed.

**An annotated host-profile template.** `config/hosts/example.json` documents
every field inline — most importantly the `memory.kind` choice, which silently
budgets against the wrong ceiling when it's wrong. It's validated by the same
test suite as the real profiles, so it can't drift out of date.

**A documented way to install the background agents.** `scripts/install-agents.sh`.

## What We Fixed

**The launchd plists no longer hardcode one person's home directory.** They did,
in eight places across two files, which meant nobody else could use them. They
are now `.plist.template` files carrying a `__CONSOLE_DIR__` placeholder that the
install script substitutes; both round-trip to valid plists.

**Twelve real public hostnames are out of the repository.** A single profile
listed every Cloudflare-tunnelled hostname for one machine. Together those are a
map of what that box exposes and what software answers on each — and six of the
twelve resolve nowhere publicly, so the repository was the only place naming
them at all. Profiles now write `https://llm.${PUBLIC_DOMAIN}`, substituted at
load time from an env var. A new test refuses to let a literal hostname back in,
and was checked by making it fail.

**The environment is documented, including what breaks without it.**
`.env.example` covers the Cloudflare Access service token, which was correctly
kept out of the repository and entirely undocumented. The useful part is the
failure mode: without it a deployed console does not report the service as down
— `fetch` follows Cloudflare's redirect, the login page arrives as a 200, the
health check only asks `res.ok`, so the service shows **green** while every call
to it returns HTML where JSON was expected.

## Key Decisions

**Redact the hostnames rather than document them.** The alternative was to keep
them and explain that a hostname is not a credential, which is true. It lost on
the six that don't resolve: for those, publishing is the disclosure, not a
restatement of one. Chose a load-time substitution over restructuring
`ServiceEntry` — it touches one function, no call sites, and no types.

**Report the hardcoding rather than fix it.** The walk turned up three places
where one machine's names are baked into shared code — `/api/metrics` hardcodes
the `vllm` service id and 502s on any host without it, the model picker hardcodes
the AI Router, and several user-visible strings say "BeTenshi" where they mean
"this machine". They are architecture, not onboarding, and are listed in the
README's Status section instead of being quietly patched.

**Dropped a screenshot rather than force it through.** The walk originally
captured the chat prompt typed-but-unsent. The distinctness invariant rejected
it — 0.9% of the frame changed, so the bytes differed but the reader would see
the same screen twice. Cutting the step was the right fix; that story is now in
the README as the clearest explanation of why the capture layer is worth using.

## The thing that nearly went wrong

**The local checkout was eighteen commits behind its own remote, and a clean
working tree hid it.** `git status` said clean, which says nothing about whether
the branch is current. Work was built, screenshotted and committed on top of a
tip that had been superseded — including a `main` branch pushed and made the
repository default while missing voice cloning, the MCP agent surface, the model
discovery panel and 3,259 lines of other work.

Caught by fetching before deleting the old `master` rather than after. Two
things then paid for themselves immediately:

- The new hostname test failed on the rebase, because those commits had added a
  fourteenth service with a literal `voice.` hostname. A guard written an hour
  earlier caught a leak arriving from a branch nobody had looked at.
- The screenshots had to be thrown away and re-taken. Between the two tips the
  Chat and Models pages had both changed materially — different latency and
  token counts, a cross-host comparison that moved out of the table into its own
  row, an entirely new Agent access section. A README shipped with the first set
  would have been wrong within a day of being written, and would have looked
  fine.

The correction also improved one finding: the newer code had already fixed the
blank telemetry panel, replacing it with a sentence explaining that Ollama
models publish no counters. The README says what is true at the real tip, not
what was true eighteen commits ago.

**Lesson: fetch before branching, not before pushing.** Clean is not current.

## Not Done

**No LICENSE file.** `package.json` claims ISC and there is no license text, so
default copyright applies and nobody may legally use or fork this. Deliberately
left for the owner — it's a declaration on their behalf, not a config change.
Flagged in the README's Status section.

## Breaking Changes

**`master` → `main`**, matching every other repository here.

# Round two — fixing what the walk found

## What We Fixed

**`/api/metrics` no longer 502s on a host without vLLM.** It asked
`getServiceUrl("vllm")` outright, so on every machine but one it threw "Unknown
service" and answered 502 on every page load. Fixed the way this codebase
already solved the same class of problem for speech: services now **declare** a
`metricsPath` in their host profile, and the route asks the profile rather than
naming a service. A host that publishes no counters is an ordinary 200 saying
so, not an error. Verified live on B5: was 502, now 200 with
`available: false`.

**"The router is down" and "this machine has no router" are now different
sentences.** The model picker hardcoded the AI Router, so B5 — whose profile
declares no router at all — was told its router was down and offered a Start
button that could never succeed. It now says, in grey rather than amber and
with no button, *No AI Router on this machine — models are called directly.*

**User-visible strings stopped naming the wrong machine.** The Requests subtitle
read "every API call across the BeTenshi stack" under a header saying B5; it now
names the live host. Grafana's description and a provider error did the same. A
fourth pointed at the wrong file — `betenshi-console/.env` where the documented
location is `.env.local`.

**Deleted 85 lines of dead header.** `<header className="hidden">` rendered
nothing and duplicated every control in `ConsoleHeader`, including a hardcoded
`<h1>BeTenshi</h1>` that would have printed the wrong machine name the moment
anyone unhid it. It also cost real time during the audit, because dead code
looks exactly like live code until you check the class name.

**Added a LICENSE.** MIT. `package.json` claimed ISC with no licence text, which
means default copyright: the repository looked open and legally wasn't.

## Key Decisions

**Declared, not inferred — again.** `metricsPath` is the third instance of the
same pattern in this codebase, after `serves` for capabilities and host profiles
for services. The rule each time: a route must never encode "the service that
happened to do this in 2025" as the definition of the capability.

# Round three — walking both machines

The first walkthrough covered one host with two services, so it showed no image
generation, no speech, no routing — most of the product. Fixed by walking both
machines. The Windows box turned out to be reachable on the LAN, so the same
script now drives either.

## What We Built

**A two-host walk.** `scripts/walk-console.mjs` takes `--host` and `--features`,
walks nine surfaces including mobile, and writes a timestamped run record. 25
captures across two machines, including a real image generated on the RTX 5090
during the run.

**The README now shows the host-profile idea instead of describing it** — the
same Home page on both machines, side by side, one offering every workstream and
one saying *Not on this machine* three times.

## What We Fixed

**Image Studio crashed for anyone opening the console from another machine.**
`crypto.randomUUID()` exists only in a secure context — HTTPS or localhost — and
a LAN IP is neither. Generate threw before sending anything, the button sat
spinning, and nothing in the UI said why. A headless box you open from a laptop
is the *normal* way to use this. Only driving it over the network surfaces it.

## What We Found And Did Not Fix

- `local-chatterbox` returns 500 for its own built-in voice; Kokoro synthesizes
  fine at the same endpoint.
- **The BeTenshi box runs code that is not in this repository** — a two-pane
  Speech Lab with voice cloning. Worth reconciling before those captures are
  treated as documentation of `main`.

## Key Decisions

**When a walk says a feature is missing, suspect the walk.** Two "missing
features" were both selector bugs. `clickText("Generate")` matched the mode tab
*and* the composer button, so the click never landed and the walk waited seven
minutes for an image nobody requested. In the Speech Lab two buttons say
*Speak*; the walk clicked the voice-cloning one, hit a microphone permission
prompt a headless browser can never satisfy, and reported the host had no TTS
service. Both produced output identical to a genuinely broken feature.

**Capture the refusal, not just the success.** The first image attempt was
rejected by the capacity guard with a 409 naming every consumer of the card —
because starting four services alongside the running vLLM over-subscribed 31.8
GB. That is the admission control working, and it is now in the README beside
the successful image.

**Leave the other machine as you found it.** Four services were started and one
stopped to make the walk possible. All were reverted, and the up-set was
compared before and after to prove it.

# Round four — the project is called Hangar

Renamed for sharing. The product is **Hangar**; `betenshi` stays exactly where
it belongs, as the id of a *machine* in `config/hosts/betenshi.json`, beside
`b5.json`. That separation is most of why the rename was cheap: of 65 files
mentioning the old name, only about twenty carried a mechanical identifier.

## What Changed

`HANGAR_DB_PATH`, `HANGAR_STORAGE_DB`, `x-hangar-target`, `hangar:` storage
keys, `com.hangar.*` launchd agents, the `hangar` theme, `hangar-*` image
filenames, `Hangar/1.0` user-agent, `package.json` name.

## What We Were Careful About

**Nobody loses their data.** The DB and storage index resolve the new location
only if the old one is absent, and both old env vars still work. Verified live:
B5 kept `~/betenshi/betenshi.db` and no empty `~/hangar` was created. Silently
pointing a renamed install at a fresh database would look exactly like losing
every record.

**No machine ends up running two agents.** `install-agents.sh` now retires
`com.betenshi.*` on install and on uninstall. Without that, an upgraded machine
runs the old and new agent on the same ports and it reads as a port conflict.

## Also Fixed

**Storage Manager returned `spawn powershell.exe ENOENT` in a 500 on macOS.**
It enumerates drives through `Win32_LogicalDisk`, so it is Windows-only by
construction. It now answers **501** with a sentence saying so. Same fix shape
as `/api/metrics`: a machine that cannot do something should say so, not fail
like a broken install.

**Removed a personal Claude routine id** from `docs/models.md` — account-scoped
and useless to anyone else — and corrected a stale `master` reference left over
from the branch rename.
