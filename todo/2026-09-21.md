# 2026-09-21 — Images work again, and now nothing claims to work without proof

Two halves. The morning was an audit of the running console
(`docs/gap-audit-2026-09-21.md`). The afternoon was the whole plan it produced.

## The problem

Every image this Mac produced through Hangar between 20 and 21 September was
high-frequency colour static, and **nothing noticed** — not the health probe,
not the adapter, not `file`, not the gallery, not the request log. The PNGs were
structurally perfect, so a model emitting noise was indistinguishable from a
working one at every single layer.

The cause was environmental. Draw Things' standalone CLI ships Metal 4
cooperative-tensor shaders (`matmul2d_descriptor`, `execution_simdgroups`) that
macOS 27's Metal compiler rejects. The pinned July build fails **silently**,
returning a valid PNG of noise; the current 26.0910.1 crashes with the shader
error. The same weights render correctly in the Draw Things GUI app, so it is
the binary, not the machine and not the model.

## What We Built

**Images generate again, on a different engine.** The image driver is now
**mflux** (FLUX.2 Klein on Apple MLX) — a different compute stack from Draw
Things' custom Metal shaders, and one already proven on this box because the
speech models use it. Verified end to end through the console UI: a lighthouse
on a cliff at dusk, 1024², 8.7 s.

**A capability is verified by its OUTPUT, never by a 200.** This is the spine of
everything else:

- `src/lib/image-quality.ts` decides whether a PNG is a picture or static, by
  measuring what fraction of neighbouring pixels match. Real images here score
  25–97%; every noise sample scored 0.6–1.5%. The threshold needs two
  independent signals to agree before it rejects anything, so a false reject
  needs two measurements wrong at once.
- `scripts/doctor.mjs` runs a **real job per capability and inspects the
  result**: an answer with one correct response, a red square shown to the
  vision model, a 512² image measured for noise, speech synthesized and then
  transcribed back, embeddings checked to score related text above unrelated.
  `--write` records only genuine passes, and **a failure clears a previous
  pass** — a stale claim is the exact lie this prevents.
- The adapter and `generateAndSave()` both gate on the same check, so a backend
  that starts emitting noise returns a 502 naming the driver instead of filling
  a gallery.

On first run: 6 verified, 1 failing. The failure is video, which correctly
caught the same broken CLI by decoding a frame and measuring it.

**Engines are declared, not assumed.** Host profiles gained a `runtimes` block —
which driver, which service, and when its output was last checked. Ten drivers
are implemented across Apple silicon, NVIDIA and CPU-only paths.

**Request history survives a restart and says what it did.** A new
`traffic_events` table in DuckDB, plus `describeCall()` so a route can report
its model, prompt, response, tokens and the image it produced. Previously only
the AI Router's callback filled those, so on a Mac — which has no router — every
local chat row carried a status and a duration and nothing else, and the detail
panel could only say *"Not previewed — re-sending a POST could repeat the
action."* Verified: restarted the console, the chat prompt, the model, the
answer and the generated image were all still there.

## What We Fixed

- **Image Studio is a studio again.** It had been replaced wholesale by a
  "paused" card gated on `getHostId() === "b5"`. That broke this console's own
  rule that availability is *shown*, never used to remove — and it is why the
  image prompt typed on Home vanished, and why "View saved images" opened an
  empty page. It is now a banner above a working studio, driven by the profile.
- **Activity is no longer permanently empty off BeTenshi.** The archive mirror
  ran only when `target === "comfyui"`, true on exactly one machine. It is now
  declared per driver (`mirrorsToArchive`), so every host's Activity feed shows
  what the subtitle promises.
- **The Run setup row named a service that does not exist here.** "Qwen-Image
  service · Local process · :8021" was two literals; on this Mac the service is
  the Local AI Toolkit on :8111. Both now come from the profile.
- **Nine native `<select>` elements** across Requests, Usage, Arena and the
  Image Studio, replaced with the project's `Select`. They rendered with
  OS-default styling that ignores dark mode.
- **"Telemetry unavailable · 0.0 / 128.0 GB" on every page load.** `gpu` is null
  both before the first fetch and when telemetry has failed, and the strip
  treated those identically — so a healthy machine asserted a broken one for
  three seconds. There is now a third state that says so.
- **The refresh loop stopped entirely in a background tab.** It now slows to a
  sixth of its rate instead. Two separate rounds of "the data is not loading"
  were this.
- **The resolver had a hostname in it.** `if (platform === "darwin") return
  "b5"` told any stranger's Mac it was B5. It now falls back to any profile for
  the same platform, deterministically.
- **The detector missed the Mac toolkit adapter** (2 of 14 known ports on a box
  serving five capabilities) and picked its text model as `models[0]`, which is
  ordered by modification time — drafting a vision model as the machine's chat
  default. It now knows :8111, picks the largest chat-capable model, and says
  plainly that the pick is a guess the doctor must prove.

## What the new tests caught

Adding `runtimes` validation to `host-profiles.test.mjs` immediately failed on
three real disagreements in the profile I had just written: a vision model that
did not match the service's declared one, and two model names that encoded the
old engine (`flux2-klein-4b-draw-things`). All three fixed. 126 tests pass.

## Key Decisions

- **The engine was the accident; the missing check was the bug.** Swapping to
  mflux alone would have fixed today and taught nothing. Every capability now
  has to prove itself, which is why video is declared, unverified, and has its
  Generate button disabled rather than quietly removed.
- **Did NOT split the Mac adapter into one process per capability**, though the
  plan proposed it. The serialisation is the feature: Draw Things, MLX and
  Ollama share one unified-memory pool and two concurrent jobs thrash rather
  than fail cleanly. Separate processes could not enforce that. The real
  complaint — that stopping speech also stops images — is a labelling problem,
  and the row now names the service it will stop.
- **Kept `draw-things-cli` as a driver** rather than deleting it. It is correct
  on other macOS versions; the doctor is what decides per machine.
- **`NEXT_PUBLIC_IMAGE_RUNTIME` is published from `next.config.ts`** rather than
  read from the profile inside `image-models.ts`. That module is loaded by the
  bundler-free `node --test` suite, where a relative TypeScript import chain
  does not resolve — the same constraint that already keeps `os` out of
  `host.ts`.

## Verified on B5

- `npm test` 126/126 · `npx tsc --noEmit` clean · `npm run build` clean.
- `node scripts/doctor.mjs` — 6 verified, 1 failing (video, correctly).
- Generated through the console UI, saved, mirrored to Activity, and shown in
  the Requests detail with its prompt and image.
- Restarted the console; the history was still there.

## Breaking Changes

None to any API. Host profiles without a `runtimes` block keep working: the
adapter falls back to its previous driver and the UI reports every capability as
unproven, which is accurate.

## Still Open

- **Video on this Mac.** Declared, unverified, disabled. Needs either a working
  Draw Things CLI or an MLX video driver.
- **BeTenshi has never been checked.** Its `runtimes` block is written but
  carries no `verifiedAt` because the doctor has not run there.
- The README screenshots predate all of this.
