# 2026-09-22 — A port is not an identity

A follow-up to yesterday, caught by yesterday's own work.

## What We Fixed

**`detect-host.mjs` identified a service by port number and a 200.** That is
two facts, and neither is identity. It was caught in the act: on 21 September
the detector reported `:4000 ai-router HTTP 200` on a Mac with no AI Router
installed and no LiteLLM on the box at all. Another project's dev server held
the port for a few minutes and would have been written into a draft host
profile as the AI Router.

The script was already careful about the opposite case — it reports a port that
answers *nothing* as unidentified, under the line "an open port is not
evidence" — and then treated any answer at all as conclusive.

**A wrong identification is worse than a missing one.** A missing service is a
gap somebody fills. A wrong one is a service the console reports as DOWN
forever while its owner debugs software they never installed.

Every entry in the known-port table now declares what its answer should look
like, and there are three outcomes instead of two:

- **identified** — it answered and the reply has the right shape
- **SOMETHING ELSE is on this port** — it answered with the wrong shape (new)
- **listening but not identified** — it answered nothing

Verified by standing up a web server on :4000 and re-running: the old code
would have adopted it, the new code names it as an impostor and explains the
cost of adding it anyway.

## What the fix got wrong first

The first version clipped the response to 8 KB **before** parsing it. The
service manager's `/services` reply is 12.9 KB, so `JSON.parse` failed and the
detector reported the real, running manager as an impostor — a confidently
wrong answer produced by the very check that exists to prevent confidently
wrong answers. Caught by running it rather than by reading it. The whole body
is parsed now, with a generous cap that exists only to avoid pulling a large
page into memory.

## Key Decisions

**Strong checks only where the shape is actually known.** Signatures are
written for the services whose replies were read on this machine (Ollama, the
service manager, the Local AI Toolkit) or fixed by a specification the service
implements (vLLM's OpenAI-compatible `/v1/models`, Grafana's health API). The
project's own FastAPI services on the Windows box have never had their health
payloads read from here, so they declare only that they speak JSON — a weak
check, labelled weak in the report, rather than a guessed one presented as
strong. A pass without a signature prints "shape not verified".

**The two browser apps opt out.** Open WebUI serves HTML from `/` and that is
correct. A shape rule written without that exception would reject the one
service it is right about.

**Split into `detect-host.probe.mjs` so the rule can be tested.** The ports in
that table are in use on any machine actually running Hangar, so an integration
test would be least reliable exactly where it matters most. Ten unit tests,
including the `:4000` case reproduced from life and a guard that fails the build
if a new table entry omits its shape declaration.

## Verified

136 tests pass, TypeScript clean, build clean. The detector correctly
identifies this machine's three real services and flags nothing falsely.
