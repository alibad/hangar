# 2026-10-26 — Second-machine setup: the engine would not start under launchd

Found while bringing a second Mac up to the connected workspace. Both bugs were
silent in a terminal and only show up on a real macOS install.

## What We Fixed

**World said "project engine is not responding" on every launchd-started Mac
console.** launchd starts the console with `PATH=/usr/bin:/bin`, and the first
`python3` there is the system 3.9. `start-engine.mjs` took the first `python3`
on PATH, so `engine/main.py` refused to run ("needs Python 3.10 or newer") and
the World page could only show its fallback. It worked from a terminal, where
the shell PATH finds Homebrew's Python first, which is why nobody saw it.
`start-console.sh` already resolves Node explicitly for the same reason; Python
was never given the same treatment. The starter now takes the first interpreter
that is actually 3.10+ (versioned names on PATH, then the usual Homebrew and
python.org locations) and only falls back to bare `python3` so `main.py` can
still say why. `HANGAR_ENGINE_PYTHON` still wins when set.

**Every project was scanned twice on macOS.** The default roots try both
`~/Code` and `~/code`. On a case-insensitive disk (the macOS default) those are
one folder, but the duplicate check compared `Path.resolve()` strings, which
keep the spelling they were given, so the first scan listed the same tree as
`CODE` and `CODE2`. The check now compares the folders themselves
(`os.path.samefile`). Machines that already have a `var/engine/roots.json` keep
it; remove the duplicate root by hand there.

## Key Decisions

- The interpreter check runs the candidate (`sys.version_info >= (3, 10)`)
  rather than parsing `--version`, so it is the same test `main.py` applies.
- Regression tests: `scripts/start-engine.test.mjs` drives the starter with fake
  interpreters on a bare PATH; the selftest builds a home with only `Code` and
  expects one root.

**The GitHub inventory said "gh is not installed" under launchd.** Same bare
PATH: Homebrew's `gh` was never visible to the console or its engine.
`start-console.sh` now adds `/opt/homebrew/bin` and `/usr/local/bin` before
resolving Node, so the engine also finds Homebrew's Python and `ollama`.
